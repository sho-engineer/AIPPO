# Feature Specification: ハンズオンレッスン1本 + AIチューター（MVP）

**Feature Branch**: `001-handson-lesson-mvp`

**Created**: 2026-08-02

**Status**: Draft

**Input**: User description: "AI初心者向けハンズオン レッスン1本とAIチューターのMVP"

## User Scenarios & Testing *(mandatory)*

対象ユーザー: **AIに興味はあるが、何に使えばよいか分からない日本の会社員**（非IT人材）。
本機能のゴールは、この人が一人で最初の成功体験（自分の文章がAIで改善された）を得ること。

### User Story 1 - 用意された題材でAIを一度動かす (Priority: P1)

初めてアプリを開いたユーザーが、レッスン「文章を分かりやすくする」を選び、
用意された選択肢から題材（例: 仕事のメール）を選び、穴埋めフォームを埋めるだけで
AIを1回実行し、改善された文章を目にする。

**Why this priority**: 「AIに何をさせればいいか分からない」という最大の障壁を、
選択肢と穴埋めで越えさせる。これ単体で「AIを一度使えた」という価値が成立する。

**Independent Test**: レッスンを開始し、題材を選び、穴埋めを埋めて実行するまでを通しで操作し、
AI出力が画面に表示されることで検証できる。以降のストーリーを実装しなくても価値が成立する。

**Acceptance Scenarios**:

1. **Given** ユーザーがレッスン開始画面にいる, **When** 「はじめる」を押す,
   **Then** 題材の選択肢が4つ表示され、チューターが `question` 表情で
   「まずは、短くて身近な文章から試してみましょう。」と案内する
2. **Given** 題材「仕事のメール」を選んだ状態, **When** 次へ進む,
   **Then** 「この文章を、【誰向け】に、【どのような表現】で、【どれくらいの長さ】にしてください。」
   の穴埋めフォームが表示される
3. **Given** 穴埋めの必須項目がすべて埋まっている, **When** 「AIに送る」を押す,
   **Then** チューターが `thinking` 表情になり、完了後に元の文章とAI出力が並べて表示される
4. **Given** 穴埋めの必須項目が空である, **When** 「AIに送る」を押す,
   **Then** 送信されず、どの項目を埋めればよいかが1つだけ示される

---

### User Story 2 - チューターのヒントで依頼内容を改善する (Priority: P2)

AI出力を見たユーザーが、チューターから「良かった点1つ・改善点1つ」を受け取り、
改善の方向（もっと短く／もっと丁寧に／具体例を追加／別の表現）を1つ選んで再実行し、
改善前後を見比べる。

**Why this priority**: 「AIに指示を足すと結果が変わる」ことの体感が、本サービスの中核学習内容。
ただし User Story 1 が成立していなければ意味を持たないため P2。

**Independent Test**: AI出力が表示された状態から、チューターのフィードバック表示 →
改善方向の選択 → 再実行 → 改善前後の比較表示までを操作して検証できる。

**Acceptance Scenarios**:

1. **Given** AI出力が表示されている, **When** 画面が表示された時点,
   **Then** チューターが良かった点を1つ、改善点を1つだけ提示する（同時に2つ以上の改善点を出さない）
2. **Given** 改善方向の選択肢が表示されている, **When** 「もっと短くしたい」を選んで再実行,
   **Then** 1回目の出力と2回目の出力が並べて表示され、チューターが違いに言及する
3. **Given** チューターのフィードバック取得が失敗した, **When** 画面が表示された時点,
   **Then** 固定のヒント文が表示され、ユーザーは改善方向の選択へ進める

---

### User Story 3 - 自分の文章で試して完了する (Priority: P2)

ユーザーが自分の実際の文章を1つ入力して同じ手順を再実行し、
自分の成果物を得たうえでレッスンを完了する。

**Why this priority**: MVP検証項目「自分の成果物を完成できるか」に直結する。
自由入力はここで初めて登場する（憲章 原則 I）。

**Independent Test**: 自由入力欄に任意の文章を入れて実行し、
結果表示 → 振り返り → 完了画面（`celebrate` 表情）までを操作して検証できる。

**Acceptance Scenarios**:

1. **Given** 改善のステップを終えた状態, **When** 自由入力欄に自分の文章を入力して実行,
   **Then** 同じ穴埋め条件が適用された結果が表示される
2. **Given** 自由入力欄が空である, **When** 実行しようとする,
   **Then** 実行されず、「用意された例文で試す」という代替の選択肢が提示される
3. **Given** 自分の文章での実行が完了した, **When** 「完了する」を押す,
   **Then** チューターが `celebrate` 表情になり、
   このレッスンで身についたことが1文で示され、成果物をコピーできる

---

### User Story 4 - 学習の記録が残る (Priority: P3)

ユーザーの操作（開始・各ステップ通過・AI実行・再実行・完了・離脱）が学習イベントとして記録され、
MVPの検証項目を後から測定できる。

**Why this priority**: ユーザーに直接見える価値ではないが、
MVPの目的が「検証」である以上、これが無いとフェーズ2の判定ができない。

**Independent Test**: レッスンを通しで操作した後、
記録されたイベント列を確認することで検証できる。

**Acceptance Scenarios**:

1. **Given** ユーザーがレッスンを開始した, **When** 各ステップを通過する,
   **Then** ステップごとに1件の学習イベントが記録される
2. **Given** ユーザーが途中で離脱した, **When** セッションが終了する,
   **Then** 最後に到達したステップが記録に残る
3. **Given** 同一ユーザーが2回目に訪問した, **When** レッスン一覧を開く,
   **Then** 前回の到達ステップが表示され、続きから再開できる

---

### Edge Cases

- **AIの応答が遅い**: 一定時間（15秒）を超えたら待機中の案内を切り替え、
  さらに超過（30秒）したら中断して再試行を促す。レッスンは進行可能なままにする
- **AIの応答が想定形式でない**: サーバー側で固定のフォールバック文言に置き換える。
  ユーザーにエラーを見せない
- **AIが利用できない（障害・上限超過）**: 固定ヒントのみでレッスンを完走できる
- **ユーザーが送信を連打する**: 実行中は再送信を受け付けない
- **ユーザーが戻るボタンで前ステップへ戻る**: 入力内容は保持され、やり直せる
- **不適切な内容の入力**: レッスンの範囲外である旨を穏当に伝え、例文での実行を提案する
- **極端に長い文章の入力**: 上限（5,000文字）を超える場合は入力時点で知らせる
- **画面幅が狭い（スマートフォン）**: チューターは画面下部に固定表示し、入力欄を隠さない

## Requirements *(mandatory)*

### Functional Requirements

#### レッスン進行

- **FR-001**: システムは、レッスンの進行状態を
  `INTRO` / `SELECT_USE_CASE` / `FIRST_INPUT` / `GENERATING` / `REVIEW_RESULT` /
  `IMPROVE_INPUT` / `REAL_TASK` / `REFLECTION` / `COMPLETE` の9状態で管理しなければならない
- **FR-002**: システムは、許可された遷移以外の状態遷移を拒否し、現在の状態を維持しなければならない
- **FR-003**: システムは、各状態においてユーザーが次に取るべき行動を **1つだけ** 提示しなければならない
- **FR-004**: ユーザーは、前のステップへ戻り、入力内容を保持したままやり直せなければならない
- **FR-005**: システムは、レッスン教材（題材の選択肢・穴埋め項目・固定文言）を
  アプリコードから分離したデータとして保持しなければならない

#### チューター表示

- **FR-006**: システムは、チューターを
  `neutral` / `question` / `thinking` / `hint` / `warning` / `celebrate` の6表情で表示しなければならない
- **FR-007**: システムは、チューターのメッセージを吹き出しで表示し、
  スクリーンリーダーへ変更を通知しなければならない（`aria-live`）
- **FR-008**: システムは、画面幅が狭い場合にチューターを画面下部へ配置し、
  入力操作を妨げてはならない
- **FR-009**: システムは、AI処理中はチューターを `thinking` 表情にしなければならない

#### AIチューターのフィードバック

- **FR-010**: システムは、`lesson_id` / `step` / `user_input` / `attempt_count` を受け取り、
  `message` / `emotion` / `action` / `hint_level` / `completed` を返すフィードバック機能を
  提供しなければならない
- **FR-011**: システムは、入力を検証し、不正な入力に対して何が不足しているかを返さなければならない
- **FR-012**: システムは、AIの出力が定義された形式に適合しない場合、
  固定のフォールバック文言に置き換えて返さなければならない
- **FR-013**: システムは、AI呼び出しが失敗またはタイムアウトした場合、
  当該ステップの固定ヒントを返し、ユーザーが進行を続けられるようにしなければならない
- **FR-014**: チューターのメッセージは100文字以内でなければならない
- **FR-015**: チューターは、1回のフィードバックで改善点を1つだけ提示しなければならない
- **FR-016**: チューターは、`REVIEW_RESULT` において、良かった点を先に1つ提示しなければならない
- **FR-017**: システムは、`attempt_count` に応じて `hint_level` を 0〜3 の範囲で段階的に上げ、
  1回目で正解そのものを提示してはならない

#### AI実行（レッスン本体）

- **FR-018**: システムは、ユーザーの穴埋め入力から依頼内容を組み立て、AIを実行しなければならない
- **FR-019**: システムは、実行中に同一内容の再送信を受け付けてはならない
- **FR-020**: システムは、ユーザーが画面を離れた場合、進行中のAI実行を中止しなければならない
- **FR-021**: システムは、1回目の出力と2回目以降の出力を並べて比較表示しなければならない

#### 学習記録

- **FR-022**: システムは、レッスン開始・各ステップ通過・AI実行・再実行・完了・離脱を
  学習イベントとして記録しなければならない
- **FR-023**: システムは、同一ユーザーの再訪時に、前回の到達ステップから再開できるようにしなければならない
- **FR-024**: システムは、外部AIプロバイダへ送信するデータを、
  当該レッスンの実行に必要なフィールドに限定しなければならない

#### 用語と表現

- **FR-025**: UIに表示する文言は日本語を第一言語とし、コードから分離して管理しなければならない
- **FR-026**: UIは、プロンプト・トークン・モデル・API等の専門用語を露出してはならない

### Key Entities

- **Lesson（レッスン）**: 学習の単位。識別子、タイトル、題材の選択肢、
  穴埋め項目の定義、各ステップの固定文言を持つ。MVPでは1件（`rewrite_text_001`）
- **LessonStep（ステップ）**: レッスン内の進行段階。9種類。
  各ステップは「ユーザーが次に取る行動」を1つ持つ
- **LearningSession（学習セッション）**: 1人のユーザーの1回のレッスン挑戦。
  現在のステップ、入力内容、試行回数、開始・完了時刻を持つ
- **TutorFeedback（チューターの発言）**: メッセージ、表情、次の行動、ヒント段階、完了フラグ。
  固定文由来かAI生成かの区別を持つ
- **LearningEvent（学習イベント）**: 学習セッションに紐づく操作の記録。
  イベント種別、発生時刻、対象ステップを持つ
- **AiRun（AI実行）**: レッスン本体でのAI実行1回分。入力条件、出力、実行順序を持つ

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初回利用者の 70% 以上が、外部の助けなしにレッスンを完了できる
- **SC-002**: レッスン開始から完了までの所要時間の中央値が 15分以内である
- **SC-003**: 完了したユーザーの 80% 以上が、自分の文章での実行（User Story 3）まで到達する
- **SC-004**: 完了したユーザーの 40% 以上が、7日以内にAIを再度利用したと回答する
- **SC-005**: AIが利用できない状態でも、レッスンの完了率が 90% 以上を維持する
- **SC-006**: チューターのフィードバック表示までの時間が、95パーセンタイルで 5秒以内である
- **SC-007**: 「次に何をすればよいか分からなくなった箇所があった」と回答する利用者が 20% 以下である
- **SC-008**: 完了したユーザーの 30% 以上が、有料プランに関心があると回答する

## Assumptions

- ユーザーはPCまたはスマートフォンのブラウザから利用し、安定した通信環境にある
- MVPでは認証を簡易なものとし、ソーシャルログイン・決済は範囲外とする
- レッスンはMVPでは1件のみ実装する。20〜30レッスンへの拡張はデータ追加で行える構造とする
- 外部AIプロバイダは1社を選定し、インターフェース経由で差し替え可能とする
- チューターの画像6枚は別途用意される。実装時は同一規格のプレースホルダで進めてよい
- 学習イベントの分析基盤は範囲外とし、MVPではデータの蓄積までとする
- 多言語対応は範囲外。文言の分離のみ行い、翻訳は将来対応とする

## Out of Scope

憲章 原則 II に従い、本フィーチャーでは以下を実装しない。

Live2D / 音声 / 口パク / 3D / 複数キャラクター / ベンダー別コース（OpenAI・Google・Anthropic） /
教材の自動生成 / ユーザー資料のアップロード / 決済 / 法人管理画面 / ソーシャルログイン /
レコメンドエンジン / AIビジネス情報 / AI活用診断（本フィーチャーでは題材の選択で代替する）
