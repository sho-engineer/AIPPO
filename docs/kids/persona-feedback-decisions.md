# 親子QAフィードバック：採否・反論・修正

判断日：2026-10-14。対象は Kids βプレビュー。前回の親子QA報告に対して、学習・UX・家庭利用の3担当が反論し、統括が採否を決めた。

## 結論

保存・削除の誤表示と入口の不一致は修正する。具体的な案・資料を比べる課題、読み補助、親の確認窓口を最小範囲で追加する。選択式の全廃、全面的な脱幼児化、能力スコア、自由な実AI会話は採用しない。

今回のペルソナは仮説。実際の子ども・親の理解、飽き、操作時間、学習効果、支払意向を測った結果ではない。再現したソフトウェア不具合と、利用者観察が必要な仮説を区別する。

## 採否と理由

## 議論で退けた案

- IQ・他児比較・能力スコアの追加：親の意欲への仮説はあるが、課題正解・自己申告から算出できない。課金のために評価を過大にしない。
- 実AI利用を進級条件にする：家庭の時間・契約・利用条件で学習を止める。カード練習とAIを使わない判断も維持する。
- 全課題を自由入力・外部AI会話へ変更：入力支援、安全確認、費用、回答評価が必要。今回の不具合修正の前提にしない。
- 全面デザイン変更・音声追加：親子観察がなく、音声不要の既存方針にも反する。公式アセットは変更しない。
- 完了数から「手助けが減った」「日常利用できる」と認定：未練習題材・別日の観察、読み上げと判断支援の区別が必要。

## 反論で追加修正した点

UX担当が「じぶんで比較」を初回に選んでも、閉じると主ボタンが基礎冒険へ戻る不具合を発見。高学年の外観と、日常課題へ進む条件を分離し、standardでも目的を保持した。

家庭担当が「確認先の選択：なし」は、その工程を扱わない初級課題で失敗に見えると反論。「この練習では扱っていません」へ修正した。

書込み・削除後の読取りだけ失敗する場合も検査に追加。保存領域での成功・失敗を断定せず、確認できた範囲と画面上の状態を報告する。

## 記録の互換性

基本schemaは3を維持。新チャレンジはrubricVersion 2として、具体案選択・資料比較の有無を記録する。旧rubricVersion 1を新証拠へ昇格しない。旧スタンプは保持し、新実践未完了のステージを解放しない。

具体案・資料は教材用の例。実際の天気・施設・料金・営業状態・AI出力ではない。保存された選択は教材内の操作証拠であり、自分で文章を作成した証拠や実生活の習得認定ではない。

## 品質確認

- 保存・削除の故障注入10ケース：成功、例外、無言失敗、部分削除、読取り確認失敗、再読込。
- 具体課題18ケース：計画・資料の各8条件組合せ、誤答ゲート・ヒント、旧証拠保持・再読込。
- 初回・再訪等9ケース：学び方選択、再開、同条件の再挑戦、旧スタンプ、未解放CTA、読み補助、親まとめ。
- 既存フロントエンド単体テスト、Lint、TypeScript込みbuild、Lesson Spec検査を実行。最新の実行結果はPRとMission Registryに記録する。
- Kidsの実画面・タッチ・画面サイズ別QAは未実施。以前の自動承認レビューが、保護されたデプロイからVercelアカウント領域へ移るブラウザ操作を拒否した。回避していない。
- 実親子への理解・援助時間・日常転用・再訪・支払意向の観察は未実施。

## 残る課題

1. 320/375/390/430pxでルビ・初回選択・候補カード・親まとめが収まるか、開始から復帰まで確認する。
2. 読むだけの支援と答えを考える支援を分け、初見の別題材で子どもが条件と根拠を説明できるか観察する。
3. 兄弟の端末共有と復元需要を確認して、複数プロフィール・読込み機能の設計を判断する。現版にはない。
4. 高学年が別の日常課題へ転用し、AIを使わない選択もできるか観察する。教材を終えただけで最終ゴール達成とは扱わない。
5. 通常公開URLと最新デプロイの対応は別途確認する。デプロイ成功を公開URL反映やKids視覚QA完了に置き換えない。

修正コードはレビュー対象。Lessonのpublished状態、公開URL、保護設定は変更していない。実ブラウザと本人観察が残るため、全体品質はPartially Verifiedとして管理する。
