# AIPPO Kids | 森ワールド Stage 1 — 最終確定仕様（Work用）

更新：2026-11-08 / 対象：**Stage 1のみ**（Stage 2〜5は詳細最終承認前）。

## 優先順位・合意事項
- 旧 `AIPPO_Work_Handoff_Stage01-05_20261108.zip` の Stage1仕様より**本書が優先**。
- この段階は**生成AIを実際に子どもの自由入力と接続しない**。まずカードで確実に完結する学習ゲームと、将来のAI解釈器に差し替えられるインターフェースを実装する。
- 機能としての任意音声入力は将来対応の設計をする。ただしブラウザでの音声認識が安全・同意・動作確認できないまま外部に子どもの音声・音声由来テキストを送らない。現時点ではカード操作だけで100%完遂できること。
- 1世界10ステージ。1〜5は**画面上の設計シミュレーション**、6〜10は実際のロケット組立→最後のStage10で発射。Stage1で実物のロケットは完成・発射しない。
- キャラは白青ロボットのポーちゃん、ピンク色の子、黄色の星形キャラの計3人。黄色星は**「ほしの子」が仮称であり、正式名として確定しない**。参考画像を優先し、ポーちゃんの目・まつ毛・アンテナ・耳の造形を勝手に改変しない。プレイヤーはロケットの乗組員に追加しない。

## 学習ゴール
子どもが「何を作ってほしいか」「何をどのように変更したいか」を自分で伝え、**実際に返ってきた結果を確認**して、必要なら修正できること。

**共通体験**：子どもが考える → AIへのお願い（カード等）→ ゲームのシミュレーション結果 → 子どもが実際の結果を確認 → 異なれば修正・再試行。いかなるお願いでも、いきなり成功演出に飛ばない。

## 導入ストーリー（吹き出しは1人ずつ・本文はUIレイヤー）
1. ポーちゃん「ねえねえ！ ぼく、うちゅうに いってみたい！」
2. 黄色の星形キャラ［仮称：ほしの子］「でも、ロケットが ないよ？」
3. ポーちゃん「そうだ！ AIに そうだんしてみよう！」
4. ポーちゃん「きみなら なんて おねがいする？」
導入アートの現行版は**仮素材**で、設計図が先に描かれている／3人の出席が不足する場合がある。ゴールと因果に合うよう修正し、ユーザー参照キャラから逸脱しないこと。

## Round 1 — 「ロケットの せっけいずが ほしい！」【確定】
- ポーちゃんは答えを先に教えない。子ども自身が「対象」と「成果物」を選ぶ。最初は未選択。
- 絵カードから `ロケット / うちゅう / ほし` と `せっけいず / え / おはなし` 等を選ぶ。5〜6歳でも分かる短いひらがなと絵を使う。
- `うちゅう + え` なら宇宙の絵、`ロケット + え` ならロケットの絵、`ロケット + せっけいず` なら**ロケット設計図**を目で見える結果として表示。
- **指示したとおりの結果**を出したうえで「でも、この結果でロケットがつくれそう？」と振り返る。結果を勝手にすり替えない。
- 最初から `ロケット + せっけいず` を選んだ子は、実際の設計図を確認したうえで進める。失敗を強制しない。
- 他を選んだ場合、間違いを叱らず「これで ロケットを つくれるかな？」と促し、自由に再入力させる。
- クリア：**ロケットの基本設計図を獲得し、結果を確認**。初期設計は次のラウンドに保持。

## Round 2 — 「おおきな まどを つけよう！」【方向性合意】
- 子どもに「そとの ほしを みたい。おおきな まどが ほしい」という**目的**を伝える。
- 既存の設計図（窓なし／小窓）を表示。子どもは変更内容を自分で組み立てて送信。
- `まどをつけて` → 小窓を追加、`おおきなまどをつけて` → 大窓を追加、`ロケットをおおきくして` → ロケットのサイズだけ変化（大窓の条件は未達）。
- **変更前と変更後**、および子どもが出したお願いを比較可能にする。既存の設計条件を保持。
- クリア：大窓が正しく追加され、表示結果を確認したこと。

## Round 3 — 「つきの いしを もってかえろう！」【B案で確定】
- 黄色星形キャラ［仮称：ほしの子］「つきに いったら、つきの いしを もってかえりたいな！」
- ポーちゃん「でも、いしを いれる ところが ないよ！」「こんどは きみに まかせた！」
- **追加課題＝月の石を安全に収納できる場所を、今のロケットの設計図へ追加**。Round 1の設計図とRound 2の大窓を維持。
- 子どもに最初から正しい指示文を見せない。選択は『なにを追加』『どこに追加』、さらに年齢帯に応じて『目的／既存条件を維持』まで考えさせる。
- 子どもの合理的な複数解（例：ロケット内部の収納箱、固定式収納スペース）を許容。空間的に無理・安全でない配置なら差分を実際に表示したうえで、理由に気づくヒントを出す。
- 例：`つきのいしがほしい` → 石の画像等が表示され、収納追加にはならない。`ロケットをおおきくして` → 本体のみ大きくなる。`いしをいれるはこをつけて` → 対応する箱が追加。`ロケットのなかにいしをしまうはこをつけて` → 内部に収納箱が追加。
- AIの発言と表示が食い違う／お願いの条件が満たされない場合に**自動クリアにしない**。子どもが実際の結果を見て、必要なら修正する。
- クリア：月の石を収納できる場所が設計図にでき、子どもが結果を確認。ペナルティなし。任意ヒントは初期非表示。
- Stage2につなぐため、翼など次の比較修正課題の余地を残す。

## 年齢別UI（初回年齢設定＋保護者が変更可）
- 5〜6歳：絵カード、短いひらがな、1〜2条件。最後のRound3でも子どもが「箱を作る／どこに置く」を自分で決める。読み上げ支援。
- 7〜8歳：カード2〜3条件の組合せ。必要なら段階的ヒント。
- 9〜10歳：既存の条件（大窓等）を保持しつつ、収納の場所・用途・変更範囲を具体的に指示できる。単純3択に閉じない。
- ヒント利用と自力達成は別に記録。ただしヒントを使ってもクリア可。入力方式（カードか音声か）は評価基準にしない。

## UI／音声／動き
- 既存のWebアプリで実装できるレイヤー式。共通ヘッダー → ステージ進捗 → ポーちゃんの吹き出し → **2D設計図プレビュー** → カード → `AIに つたえる！` ボタン。スマホの安全領域を確保し、原則スクロールなし・タップでUI全体が下へずれない。
- ポーちゃんは説明者ではなく**相棒**。吹き出しは1個ずつ動的に切り替え、表情差分を活用。
- 導入：ユーザーが開始操作後、任意の読み上げを自動再生できる（ブラウザの再生制約を尊重）。タスク内：再生ボタンで再読。音なしでも完結。
- 0.2〜0.6秒程度の短いアニメーション。カード選択／お願い送信／パーツ出現／成功を演出。視覚過敏や `prefers-reduced-motion` に対応。
- 選択カードはタップ操作、ドラッグ必須にしない。選択前の状態から構成。AI実行前の単なるプレビューと**AIにお願いした後の実際の結果**を区別して見せる。
- `references/UI_Reference_Generated_Visual_Only.png` は見た目の方向性の参考であり、その画像を背景ベタ貼りして操作領域を作らない。AI生成デザインは字・密度・キャラ造形などを本番向けに調整。

## 2D描画エンジン【確定】
- React + SVG／透明PNGのレイヤーで、**予め用意したパーツ**をID／属性／配置スロットに基づいて合成する。ロケットの設計をステージを跨いで状態保存する。
- `ユーザーの依頼（意図） -> 意図解析（現時点ではカードの決定論的マッピング） -> 構造化した変更命令 -> 検証 -> 状態反映 -> 実際の描画 -> 子どもによる確認`。
- 将来GPTに置き換えるのは**意図解析**の部分。描画・判定はゲーム側に残し、生成AIに座標やクリア判定を無条件に決定させない。
- 変更しないパーツを維持する。座席・装飾の後続ステージとの矛盾を防ぐ。位置・サイズ・色・重なり順・コックピット座標はパーツごとのスロット定義で一元管理する。
- **実装上のミス**（「いすの下」の構造化結果が画面では上に見える等）はバグ。ユーザーが明確に言ったこととAIの認識間違いは分ける。意図的なAIの誤回答は比較・検証を学ぶ対象ラウンドでのみ別途設計し、通常ラウンドで根拠なく故意に誤らせない。
- 未対応の自由指示やパーツは勝手に別の結果へ変換しない。正直に「まだ その つくりかたは できないよ」等と示し、選び直せるカードを案内。
- **結果を必ず見せる**。お願い文・結果状態・レンダリング結果をセットで管理し、子どもが確認操作を終えるまでクリアしない。誤った配置、取り落とした条件、知らない間の削除を検出できるQAを作る。

構造化命令例（座標そのものはAIが返さない）：
```json
{ "action": "add", "part": "storage_box", "anchor": "rocket_interior", "position": "inside", "size": "small" }
```

**状態の最低要件**：`designReady`, `largeWindow`, `storageBoxPlacement`, `originalRequest`, `structuredCommand`, `actualRenderState`, `roundCompleted`, `hintCount` 等。最後の状態を必要に応じて永続化。

## リグレッションQA（最低）
1. R1：選択前は何も勝手に選ばれない。3種類の異なる依頼→3種類の実際の結果。正解を初手で選んでも失敗強制なし。
2. R2：小窓／大窓／本体拡大が正しく分かれ、前後比較ができ、R1の設計図を保持。
3. R3：月の石の収納に合理的な複数の解を許容。箱の表示位置と内部状態を一致させる。R2の大窓は消えない。
4. 毎Round：入力→応答→**見た結果の確認**→必要なら修正。表示なしの自動クリアはNG。
5. 安全・不正な結果を成功扱いにしない。解釈できない依頼を勝手に変えない。
6. 5歳／10歳、iPhone Safari／デスクトップ相当のレスポンシブ、safe area、戻る・再開、音なし／読み上げONでテスト。
7. 既存アプリの他ステージ・マップ・レイアウトを破壊しない。キャラ画像は参照と一致。Stage2〜5の仕様・実装は勝手に確定しない。
8. スクリーンショット・変更ファイル・未解決事項・再現手順をレポートし、**本番公開は承認後**。
