# AI Generation Policy

Lesson の中で AI を呼ぶときの決まり。

---

## Prompt に必ず書くもの

| 項目 | 何を書くか |
|---|---|
| User input | 学習者が入れるもの（本文・選んだ条件） |
| System / Lesson instruction | AI にさせること。Lesson ごとに固定 |
| Conditions | 学習者が足した条件。1つずつ積み上がる |
| Output format | 返ってくる形 |
| Expected behavior | 条件を変えたときに何が変わるか |
| Failure handling | 失敗したときに何が残り、どこへ戻るか |
| Prompt version | 数字。変えたら上げる |

Lesson Spec の `prompts[]` がこの形（`content/lessons/_template.yaml`）。
Validator が空を **Error** にする。

---

## 作業宣言を返させない

**完成物だけを返す。** 次のような前置きを書かせない。

- 承知しました
- 以下のように書き直します
- ご要望に合わせて
- まとめると以下のとおりです

理由は2つ。読む人が探しているのは結果そのもので、前置きはそこへ
たどり着くまでの邪魔になる。そして**そのまま仕事に貼れない**——
毎回1行目を消す手間が要る。

Validator は、`system_instruction` にこれらの語が混ざっていたら
**Error** にする。

---

## モデルと実行

| 項目 | いま |
|---|---|
| Provider | `AI_PROVIDER` 環境変数（`mock` / OpenAI） |
| Model policy | Provider 側の既定に従う。Lesson ごとに指定しない |
| Timeout | `backend/apps/ai/` の設定に従う |
| Retry | **自動で複数回やり直さない**。押し直しは学習者が決める |
| Rate limit | `AI_RUNS_PER_DAY` / `AI_RUNS_PER_IP_PER_DAY` |

**AI_PROVIDER=mock のままで Lesson を完走できること。** CI はキー無しで
通る（憲章 原則 III）。

Provider を勝手に差し替えない。

---

## 入力の扱い

学習者は次のようなものを貼る。

- メール / 会議メモ / 長いチャット / 顧客情報 / 社内資料

### 空の入力

送らせない。入力欄の下で「まだ書かれていない」と伝え、CTA を押せない
ままにする。AI を呼んでから「空でした」と返さない。

### 長い入力

上限は `step.validationRules.maxLength`（既定 5000字）。超える分は
切らずに、入れる前に文字数を出す。

### 機密・個人情報

**送る前に伝える。** 入力欄には必ず `SafetyNote placement="input"` を
出す（要件 §15。文は変えない・消さない）。

スクリーニングは `PrivacyDialog`。API キーらしき文字列は送信を止め、
メールアドレスなどは読んだうえで送れる。**見つけた中身そのものは
画面に出さない**（出すと、そこでもう一度晒すことになる）。

### 外部へ送られるもの

Provider へ渡るのは、Prompt に組み立てた**本文と条件だけ**。
アカウント情報・メールアドレス・学習履歴は渡さない。

---

## 記録（Logging）

| 残す | 残さない |
|---|---|
| どの Lesson のどのステップか | 入力本文 |
| Provider / model / トークン数 / 所要時間 | AI の出力本文 |
| 成否とエラー種別 | 個人を特定できるもの |

**本文はログに残さない。** 障害調査のために本文が要るときは、
その都度の同意を取る——「調査のために残していた」を既定にしない。

---

## 失敗したとき

| 種類 | 画面 |
|---|---|
| 届かなかった（`failed`） | 押し直せる。入力と条件は残る |
| 結果が使えない（`unusable`） | 押し直し以外の道を出す（`course/rescue.ts`） |
| 混み合っている（`limit`） | 押し直せる。時間をおけば直ると伝える |
| 今日の上限（`out_of_credits`） | 専用画面。押し直す道は出さない |

**どの失敗でも、入力と選んだ条件を消さない。** 消すと、書き直しの
手間がそのまま学習をやめる理由になる。

学習者を評価する言葉を出さない（「不正解」「失敗しました」）。
起きたのは AI の出力のばらつきで、書いた人のせいではない。

---

## 要法務確認

次はここで確定しない。**法務の確認が要る。**

- 利用規約・プライバシーポリシーの本文
- 入力データの保持期間の約束
- Provider との契約上の「学習利用しない」の表明
- 業種別の規制（医療・金融・士業）に触れる案内文

本番で仕事の文章・機密情報・個人情報を扱う場合は、**Free Tier 前提で
運用しない**。Paid Tier を前提にし、入力を学習利用されない設定・契約
条件を優先する。
