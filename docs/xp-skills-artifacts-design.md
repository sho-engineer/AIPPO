## なぜ先に書くか

この4つは互いに参照し合う。

```
Lesson ──獲得──▶ AI技 ──並べる──▶ AI技図鑑
   │                 ▲
   └──作る──▶ 成果物 ─┘（この技を使って作った、が辿れる）
   │
   └──終える──▶ XP ──▶ Level
```

どれか1つを先に作ると、残り3つが最初の形に引きずられる。
特に **AI技の粒度**は、決めたあとで変えると図鑑・成果物・Lesson の
すべてに migration が要る。

## 1. AI技（AiSkill）

### 名前は一般用語にする

要件どおり、AIPPO独自の造語を作らない。図鑑で覚えた言葉が、
外の記事や他のツールでそのまま通じないと、学んだ意味が半分になる。

初回はこの12個を提案する（要件の一覧から、初心者に要るものだけ）。

| slug | 表示名 | ひとこと |
|---|---|---|
| `target` | ターゲット指定 | 誰が読むのかをAIに伝える |
| `tone` | トーン指定 | 文章の雰囲気を指定する |
| `role` | ロール指定 | AIに立場を与える |
| `context` | コンテキスト | 背景情報を先に渡す |
| `output_format` | 出力形式の指定 | 箇条書き・表など形を決める |
| `length` | 長さの指定 | 何行・何文字かを伝える |
| `few_shot` | 例示（Few-shot） | お手本を1〜2個見せる |
| `follow_up` | 追加質問 | 足りない情報をAIに聞かせる |
| `iteration` | 反復（Iteration） | 一度で決めず、直しを重ねる |
| `comparison` | 比較 | 複数案を出して見比べる |
| `decomposition` | 分解 | 大きな課題を小さく割る |
| `self_check` | 自己評価 | AIに自分の答えを点検させる |

**「プロンプトチェーン」は初回に入れない。** 要件の候補にはあるが、
複数の呼び出しをつなぐ仕組み自体がまだ無い。できないことを
図鑑に載せると、開いた人が行き止まりに当たる（憲章 原則 I）。

### モデル

```
AiSkill
  slug            一般用語の英語。URLと図鑑の並びに使う
  name            表示名（日本語）
  one_line        ひとことで（図鑑の一覧に出る1行）
  description     もう少し詳しく
  example         「取引先向けに丁寧にしてください」のような実例
  use_cases       メール / 資料 / SNS …（配列）
  how_to_use      「○○なトーンで」と伝える
  order           図鑑の並び順
```

```
LessonSkill        Lesson ⇄ AiSkill（多対多）
  lesson, skill, order
```

```
UserSkill          誰がいつ獲得したか
  user or learner_key    ← 論点A
  skill
  first_lesson           どのレッスンで初めて取ったか
  acquired_at
  unique(user, skill)    二重獲得を防ぐ
```

### Combo（P1-6）

**テーブルを作らない。** 組み合わせは「見せ方」であって、
持ち物ではない。`AiSkillCombo` を作ると、技を1つ足すたびに
組み合わせの管理が増える。

```
AiSkillCombo（表示用の定義。DBではなくデータで持つ）
  skills: [target, tone] → label: "伝わる文章"
```

正式名は一般用語のまま。コンボの名前は**その組み合わせの効果**に
付けるだけで、技の名前を置き換えない（要件どおり）。

## 2. XP / Level（P1-3）

### Credit とは別物にする

要件の「XPとCreditを同一にしない」を、モデルの段階で分ける。

|  | XP | Credit |
|---|---|---|
| 何を表すか | 学んだ量 | 使える残高 |
| 減るか | **減らない** | 使うと減る |
| 出どころ | 学習だけ | 節目の特典 |
| 置き場所 | `UserXp`（新） | `CreditTransaction`（既存） |

**XPは絶対に減らさない。** 減る仕組みを入れると、
「失う恐怖で続けさせる」設計になる。ここは既存の方針
（ランキング無し・他人との比較無し・連続記録で脅さない）と揃える。

### 配点（要件どおり）

```
lesson_completed        +20
ai_skill_acquired       +10
course_checkpoint       +30
```

### モデル

```
XpEvent            何で増えたかを1件ずつ残す
  user or learner_key
  kind               lesson_completed / ai_skill_acquired / checkpoint
  source_id          lesson.slug など
  amount
  created_at
  unique(user, kind, source_id)   ← 二重加算を防ぐ（Creditと同じ考え方）
```

合計は `XpEvent` の SUM で出す。別に残高カラムを持たない
——2か所に持つと必ずずれる（Credit で同じ判断をしている）。

### Level

**テーブルにしない。** XPのしきい値から計算で出す。

```python
LEVELS = [(0, "AI Starter"), (100, "AI Beginner"), (300, "AI User"), (600, "AI Explorer")]
```

名称を後から変えられる、という要件はこれで満たせる（定数を直すだけ。
migration も再計算も要らない）。

## 3. 成果物（SavedArtifact / P1-9・P1-10）

```
SavedArtifact
  user or learner_key    ← 論点A
  lesson
  title                  既定は「{レッスン名}で作ったもの」。あとから直せる
  artifact_type          text / image（いまは text のみ）
  user_input             元の入力
  final_output           AIの出力
  skills                 使ったAI技（多対多。図鑑から辿るため）
  created_at, updated_at
  unique(user, lesson, final_output_hash)  ← 論点B（二重保存の防ぎ方）
```

### 「保存したもの」との統合（P1-10）

いまの「保存したもの」は**レッスンへの目印（ブックマーク）**で、
成果物とは別物。名前だけ似ているので混ざりやすい。

```
学習記録    = 何を学んだか   （既存の履歴）
AI技図鑑    = 何ができるか   （新）
マイ成果物  = 何を作ったか   （新）
あとで見る  = 何を読みたいか （既存のブックマーク）
```

要件は「保存したものと統合」だが、**4つ目（あとで見る）は残す**ことを
提案する。用途が違い、統合すると「読みたい教材」と「作った物」が
同じ一覧に並ぶ。消すのではなく、名前を分けて役割をはっきりさせたい。

## 決めていただきたいこと

### 論点A: ゲストの扱い（**これが一番大きい**）

XP・AI技・成果物を、**登録していない人にも持たせるか。**

| | 持たせる | 登録者だけ |
|---|---|---|
| 良い点 | 登録前から手応えがある。憲章の「登録なしで完走できる」と揃う | 作りが単純。引き継ぎが要らない |
| 悪い点 | 登録時の引き継ぎ（`claim_guest_data`）に3種類とも足す必要がある | 登録するまで図鑑が空。**やった分が消えたように見える** |

いまのスタンプ・進捗は `learner_key` でゲストにも持たせている。
**揃えるなら「持たせる」**だが、引き継ぎの実装が3つぶん増える。

### 論点B: 成果物の二重保存の防ぎ方

同じレッスンを2回やって、同じ出力が出たとき。

1. 出力のハッシュで弾く（同じ物は1つ）
2. レッスンごとに1つだけ（新しいので上書き）
3. 何個でも残す（利用者が消す）

要件は「duplicate saveを防止」だが、**どこまでを重複と呼ぶか**が
決まっていない。1を推す（同じ条件で作り直した物は増やさない、
違う条件で作った物は別物として残る）。

### 論点C: AI技12個は多いか

図鑑の初期表示が「12 / 12」だと、集める余地が無い。
要件の例は「12 / 48」なので、**先に48個ぶんの枠を定義して、
Lessonが対応した分だけ獲得可能にする**のが近い。

ただし**中身の無い枠を並べると、押しても何も無い項目**が
36個できる。「Lesson XXで習得」と書ければ行き止まりにはならないが、
そのLessonがまだ無い場合は書けない。

12個から始めて、Lessonが増えるたびに足すのを推す。
