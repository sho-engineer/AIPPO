# 画像を作るレッスンの土台

「AIで画像をつくる」コースを実装するときの設計。**まだ作っていない。**
いま入っているのはコースとレッスンの一覧だけで、近日公開として止めてある。

この文書の目的は、作り始める人が最初の30分で迷わないようにすること。
とくに「既存の何を変えずに済むか」をはっきりさせておく。

## なぜ先に作らないか

画像生成は、文章生成と費用の桁が違う。1枚あたりのコストは文章1回の
数十倍になることがあり、レッスンは1本で最低2回（最初の1枚＋条件を足した
1枚）生成する。誰でも押せる状態で出すと、公開初日に費用が読めなくなる。

止めているのは仕組みが無いからではなく、**費用の見通しを立ててから
開けるため**。開けるときは、1日あたりの上限（既存の
`AI_RUNS_PER_IP_PER_DAY` と同じ考え方）を画像側にも別枠で持たせる。

## 既存の何を変えないか

- `AIProvider`（`apps/ai/providers/base.py`）… 文章用の口はそのまま。
  画像を同じ `generate()` に相乗りさせない。返すものが文字列と URL で
  違い、失敗の種類も違う（生成拒否・サイズ違反など画像固有のものがある）
- `apps/ai/actions.py` の紐づけ … 文章のアクション表はそのまま
- レッスンの進行（`course/engine.ts` と `flow.py`）… ステップの並べ方は
  文章のレッスンと同じ。**画像でも骨格は変えない**

## 分け方

```
AIProvider          … いまあるもの。文章
  generate(AIRequest) -> AIResponse

ImageProvider       … 足すもの。画像
  generate_image(ImageRequest) -> ImageResponse
```

`ImageRequest` に入れるのは、教材が決められるものだけにする。

| 項目 | 例 | 誰が決めるか |
|---|---|---|
| `subject` | おしゃれなカフェ | 利用者 |
| `mood` | 明るく開放的 | 利用者（選択肢から） |
| `composition` | 真上から | 利用者（選択肢から） |
| `style` | 写真風 | 利用者（選択肢から） |
| `aspect` | 縦長 | 利用者（選択肢から） |

文章のときと同じで、**プロンプトそのものは教材データに持たせない**。
組み立てはサーバー側（`apps/ai/image_actions.py` を新設）で行う。
画面から任意の文字列を送れる作りにすると、安全の決まりを1か所で
守れなくなる。

## 特定の提供元へ寄せない

`ImageProvider` は抽象のまま置き、実装（OpenAI / Google / ローカル）は
`AI_IMAGE_PROVIDER` で差し替える。文章側と同じ形にする。

既存の `registry.py` と同じ作りにできるが、**同じレジストリに混ぜない**。
文章のプロバイダ一覧に画像が混ざると、「文章用に選んだつもりのモデルで
画像が出る」設定ミスが起きる。表は分ける。

## 画像は保存する。文章は保存しない

いまのアプリは、利用者が書いた文章もAIの返答も保存していない
（プライバシーポリシーにそう書いてある）。画像は同じにできない。

- 生成した画像は URL で返ってくる。提供元の URL は数時間で切れることが多い
- 完了画面の「今回の成果物」で見せるには、その間だけでも手元に要る

決め方を先に書いておく。

1. 既定は**端末に置く**（IndexedDB か、data URL のまま localStorage）。
   サーバーへ送らないので、プライバシーポリシーを書き換えずに済む
2. 登録した人が「残す」を選んだときだけ、サーバーへ保存する。
   そのときはポリシーに1文足す（何を・どれだけ預かるか）

**黙ってサーバーへ保存しない。** これは実装の都合ではなく約束の話で、
あとから変えると「前は保存していなかったもの」が増えることになる。

## 画面の部品

文章の結果と同じ部品を流用しない。読むものと見るものでは、
必要な大きさも並べ方も違う。

| 部品 | 受け持ち |
|---|---|
| `ImageGenerateStep` | 送っているあいだ。ポーは thinking、文は「イメージを形にしています…」 |
| `ImageResult` | できた1枚を大きく出す。下に「今回AIに伝えたこと」 |
| `ImageCompare` | 最初の1枚 → 足した条件 → 変わった1枚。**縦に積む** |
| `ImageStyleChoice` | 調子を選ぶ。見本の小さな絵を添える |
| `ImageCompositionChoice` | 構図を選ぶ。図で示す（文字だけでは伝わらない） |

`ImageCompare` を縦に積むのは、文章の比較で分かったことと同じ理由。
スマホの幅で2枚を横に並べると、1枚が160pxほどになり、
「何が変わったか」を見るには小さすぎる。

## 待たせ方

画像は文章より遅い（10〜30秒）。文章と同じ「送っています…」だけでは、
止まったのか動いているのか分からない。

- ポーは thinking のまま、アンテナを淡く光らせる（いまの作りをそのまま使う）
- 出来上がる場所に、同じ縦横比の薄い枠を先に置く。
  出来た瞬間に画面が飛び跳ねない
- 30秒を超えたら「まだかかっています。待つ／やめる」を出す。
  黙って待たせ続けない

## 最初に作る1本

`image_first`（はじめてAIで画像を作る）だけを先に通す。

理由は文章のレッスン1と同じで、**1本を最後まで通すと、足りない部品が
すべて洗い出される**ため。5本ぶんのデータを先に書いても、
1本目で作りが変われば全部書き直しになる。
