# AIチューター設計

**最終更新**: 2026-08-02

学習を案内するキャラクター「チューター」の設計方針。
実装は `specs/001-handson-lesson-mvp/` の spec / plan / tasks に従う。

---

## 1. 設計の基本方針

最初から高度なAIエージェントにせず、**決められた学習フロー ＋ 一部だけAI生成** とする。

作り方を3つに分ける。

1. キャラクター画像を作る
2. 画面上で表情・吹き出しを切り替える
3. ユーザーの操作に応じてチューターの発言を生成する

---

## 2. キャラクター画像

### 2.1 基本デザイン

まず正面向きの基本デザインを1枚作る。方向性は次のとおり。

- 20〜40代の会社員が使っても子どもっぽくない
- 人間でも完全なロボットでもない
- 丸みのある小さなナビゲーター
- シンプルな服装
- 特定のAI企業を連想させない
- 背景透過
- 上半身または全身
- アプリ右下に表示しても判別できるデザイン

基本デザインを確定したら、**その画像を元に表情違いを作る**。
毎回ゼロから生成すると別キャラクターになりやすいため、基本画像を編集して表情だけ変更する。

### 2.2 必要な6種類

| 表情キー | 用途 |
| --- | --- |
| `neutral` | 通常 |
| `question` | 質問・首を傾ける |
| `thinking` | 考えている（AI処理中） |
| `hint` | ヒントを出す |
| `warning` | 注意を伝える |
| `celebrate` | 課題完了を喜ぶ |

### 2.3 ファイル構成と規格

```
frontend/
└── public/
    └── tutor/
        ├── neutral.webp
        ├── question.webp
        ├── thinking.webp
        ├── hint.webp
        ├── warning.webp
        └── celebrate.webp
```

- サイズはすべて 512×512px
- 背景透過
- WebP（フォールバックが必要なら PNG）
- キャラクターの位置と大きさを全画像で統一する

最初は静止画でよい。アニメーションは CSS で少し上下させる程度にする。

## 3. 型定義

```ts
export type TutorEmotion =
  | "neutral"
  | "question"
  | "thinking"
  | "hint"
  | "warning"
  | "celebrate";

export type TutorAction =
  | "wait"
  | "retry"
  | "next"
  | "show_hint"
  | "complete";

export interface TutorMessage {
  message: string;
  emotion: TutorEmotion;
  action: TutorAction;
}
```

## 4. チューターの役割を限定する

AIチューターに何でも自由に話させると、教材の進行が崩れる。
アプリ側で学習の段階を管理し、チューターはその段階に応じた短い説明やヒントだけを出す。

```
INTRO
  ↓
SELECT_USE_CASE
  ↓
FIRST_INPUT
  ↓
GENERATING
  ↓
REVIEW_RESULT
  ↓
IMPROVE_INPUT
  ↓
REAL_TASK
  ↓
REFLECTION
  ↓
COMPLETE
```

段階ごとのルール例:

| 段階 | チューターのルール |
| --- | --- |
| `FIRST_INPUT` | 正解を直接作らない / 一度に一つだけ質問する / 必要なら穴埋め形式を示す |
| `REVIEW_RESULT` | 良かった点を一つ伝える / 改善点を一つだけ伝える / 次の操作を明確にする |

## 5. AIを使う部分と使わない部分

すべての発言をAIに生成させる必要はない。

### 固定文でよい部分

- レッスン開始
- ボタンの説明
- 次の操作
- 完了メッセージ
- 基本的な安全上の注意
- エラー表示

### AIに生成させる部分

- ユーザー入力へのフィードバック
- AI回答の改善点
- ユーザーに合わせた例
- 次に試せる用途の提案
- 自由入力された課題へのヒント

これにより、API料金と応答の不安定さを抑えられる。

## 6. API 契約

### リクエスト

```
POST /api/tutor/feedback/
```

```json
{
  "lesson_id": "rewrite_text_001",
  "step": "review_input",
  "user_input": "このメールをいい感じにしてください",
  "attempt_count": 1
}
```

### レスポンス

```json
{
  "message": "何を伝えたいメールなのか、目的を一つ追加してみましょう。",
  "emotion": "hint",
  "action": "retry",
  "hint_level": 1,
  "completed": false
}
```

レスポンス形式は固定する。AIの出力がこの形式に適合しない場合、
サーバー側でフォールバックのヒントに置き換えて返す（憲章 原則 III）。

## 7. AIへの指示（システムプロンプト方針）

AIへの指示には、キャラクターの性格と出力制限を入れる。

```
あなたはAI初心者向け学習アプリの案内役です。
対象者は、AIに興味はありますが、
何に使えばよいか分からない非IT人材です。

役割:
- ユーザーを否定しない
- 専門用語を使わない
- 一度に一つだけ改善点を伝える
- 正解をすぐに出しすぎない
- まず良かった点を一つ伝える
- 次に行う操作を明確にする
- 100文字以内で回答する

現在のレッスン:
文章を分かりやすくする

現在の段階:
最初のAIへの依頼内容を確認する

評価項目:
- 目的が書かれているか
- 対象者が書かれているか
- 希望する文章形式が書かれているか

JSONのみを返してください。
```

返却形式を固定する。

```json
{
  "message": "",
  "emotion": "neutral",
  "action": "retry",
  "hint_level": 0,
  "completed": false
}
```

## 8. 最初のレッスン例：文章を分かりやすくする

### ステップ1 — 対象を選ぶ

> どの文章を分かりやすくしたいですか？
> ・仕事のメール ・長い説明文 ・難しい文章 ・自分の文章

チューター: 「まずは、短くて身近な文章から試してみましょう。」

### ステップ2 — 穴埋めで入力する

```
この文章を、
【誰向け】に、
【どのような表現】で、
【どれくらいの長さ】にしてください。
```

チューター: 「誰が読む文章なのかを伝えると、AIの回答が変わります。」

### ステップ3 — AIを実行する

チューター: 「最初の文章と比べて、読みやすくなったところを確認してみましょう。」

### ステップ4 — 改善点を一つ選ぶ

> ・もっと短くしたい ・もっと丁寧にしたい ・具体例を追加したい ・別の表現も見たい

### ステップ5 — 自分の実際の文章で試す

チューター: 「次は、実際に使いたい文章を一つ入力してみましょう。」

### ステップ6 — 完了する

チューター: 「AIに『文章を直して』と頼むだけでなく、相手や長さを伝えられるようになりました。」

## 9. 実装の進め方（作業単位）

| 順番 | 作業 | 主な成果物 |
| --- | --- | --- |
| 1 | 表示だけ作る | `PoeAvatar` コンポーネント + コンポーネントテスト |
| 2 | レッスン進行を作る | `useReducer` による状態管理 + 単体テスト |
| 3 | Django API を作る | `POST /api/tutor/feedback/` + Serializer + サービスクラス + モックテスト |
| 4 | 接続する | fetch + AbortController + 二重送信防止 |
| 5 | E2E テストを作る | Playwright（AI はテスト用レスポンスに差し替え） |

各作業の詳細な受け入れ条件は `specs/001-handson-lesson-mvp/tasks.md` を参照。
